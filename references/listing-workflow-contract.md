# 跨境吴老师 Amazon 新品 Listing 文案运行契约

本契约适用于根据参考竞品 ASIN 为尚未上架新品撰写 Listing 的任务。参考竞品和新品 ASIN 的角色必须分开：竞品数据只能说明需求、关键词方向和表达边界，绝不能成为新品事实或新品表现。

## 0. 阶段零：卖家精灵 MCP 配置核验

在收集 ASIN、输出四阶段提示或进行任何数据调用前，必须先读取 `sellersprite-mcp-configuration-gate.md` 并完成配置核验。只有卖家精灵连接已在**当前会话**暴露，且可唯一绑定 `asin_detail`、`review` 与 `traffic_keyword` 三项能力，阶段零才通过。服务已添加但未启用、没有暴露工具、工具归属歧义、关键输入/输出无法确认、连接鉴权/初始化失败，均视为未通过。

阶段零未通过时，只说明缺少的配置或能力，并要求用户在当前运行环境完成连接配置、启用/授权并重新加载工具目录；不得执行阶段一、读取竞品数据、切换数据源、猜测工具名，或擅自编辑配置文件。用户说“已配置”后必须重新检查当前会话的连接与工具目录，不能沿用旧结果。配置门槛的完整判断与用户提示见 `sellersprite-mcp-configuration-gate.md`。

## 1. 输入、有效规范与规则优先级

开始阶段一的必填项是：至少一个参考竞品 ASIN 和 Amazon 站点。规范化 ASIN 时去除首尾空格、转大写、按完全相同 ASIN 去重并保留原输入顺序；以已绑定的商品详情工具在目标站点的结果为唯一有效性判断，不因纯数字或预设正则直接拒绝。

同时收集并登记下列项：新品品牌词、主品类词、已确认新品事实、是否有变体及已确认变体变量、目标页面语言、用户确认的站点/类目/账号限制。缺少品牌、主品类或事实时可执行阶段一；不得生成阶段二至四的最终页面文案。

默认内部规范：标题最多 74 个 Unicode code points；商品亮点为 124–125 个 Unicode code points；ST 最多 250 UTF-8 bytes。首段 5 个关键词单元、上述长度和 ST 规则只是内部交付规范，不能说成 Amazon 平台新规。

用户明确提供的规则只替换其指明的字段。先建立并在最终文件记录：`有效标题格式`、`有效标题上限`、`有效商品亮点区间`、`有效 ST 上限`、`规则来源`。若必要字段无法同时满足有效标题格式和长度上限，或用户规则彼此冲突，暂停并请用户选择覆盖项；不要自行取较宽松规则。

页面语言默认随站点：US/UK/AU/CA/IN 为英文、JP 日文、DE 德文、FR 法文、IT 意大利文、ES/MX 西班牙文、BR 葡萄牙文、AE 英文；用户明确的页面语言优先。流程沟通、证据说明和表格检查可用中文，5 条成品、标题、亮点与 ST 必须是目标页面语言。

## 2. 事实、安全与原创边界

- 不得称新品已有评论、销量、排名、历史表现、认证或未确认变体。
- 不得复制或改写竞品标题、五点、A+、评论原文或关键词排列；评论只归纳需求、顾虑、场景与表达方向，单一原文引用不超过 25 个字符且默认不展示。
- 不得使用竞品品牌、店铺、型号、商标、专利、独家设计或可识别资产。
- 材质、尺寸、颜色、数量、认证、适配对象、包装、性能参数、变体均须有用户资料或明确确认。多竞品共有也不能转为新品事实。
- 所谓“合规检查”只表示事实、夸大和明显文案风险检查，不宣称已通过 Amazon 审核或任何法律/监管审核。

## 3. 数据路由与完整性账本

仅在阶段零通过后，动态绑定属于卖家精灵的 `asin_detail`、`review`、`traffic_keyword` 业务能力。工具名、字段投影、包装层、页码、游标、单批上限和可写目录均由当前 schema/响应决定。无法唯一绑定工具时报告 `blocked: tool_binding_ambiguous`；不可用时不得切换其他来源补推。

对所有 ASIN 先取基础详情（ASIN、标题、品牌、类目路径/语义及可用属性）。基础详情失败、无效或站点不匹配时，列出 ASIN 和原因，等待用户“移除、替换或确认排除”。未经授权不能进入候选池。若类目/产品语义不一致，按类目和标题分组，等待用户确认同类组；无法判定时停止。

对获准纳入的 ASIN 分别取页面属性、评论和流量关键词。分页以当前响应的总页数、游标、空记录、少于请求条数或重复页面为停止条件；临时错误只重试失败请求最多 2 次（服务返回 Retry-After 时按服务要求）。不得打印原始响应。

维护可交付账本：

| 维度 | 成功 | 无记录 | 未获取 | 分母 |
| --- | --- | --- | --- | --- |
| 基础详情 | 已核验并纳入的 ASIN | 不适用 | 无效/失败/待排除 | `M_detail` |
| 评论 | 实际可读取或确认空列表的 ASIN | 成功空列表 | 绑定、schema、分页或调用失败 | `M_review` |
| 流量关键词 | 基线请求可读取或确认空列表的 ASIN | 成功空列表 | 绑定、字段映射或调用失败 | `M_keyword` |

详情是硬阻塞项。评论或关键词出现部分未获取时，先展示缺口和可用分母，等待用户明确确认“使用部分证据继续”才可产出候选池；若用户不确认则停在阶段一。候选证据必须分别标注 `页面 N/M_detail`、`评论 N/M_review` 或 `关键词 N/M_keyword`，不能把不完整数据混成同一 `N/M`。

### 页面、评论和关键词的取数边界

- 页面：对每个已纳入 ASIN 取 ASIN、标题、品牌、商品特性/概述、父子体、价格、评分/数量、上架时间、尺寸重量与标识等 schema 实际可返回字段。标题/features/overviews 只作候选方向；竞品变体不能成为新品变体。竞品 A+ 不是必需路由。
- 评论：从允许的第 1 页开始读取；如 schema 支持则目标每页 20 条。只内部清洗标题、正文、星级、时间等实际字段，用于需求和顾虑归纳。
- 关键词：对每个 ASIN 先发无 `returnFields`、无 badges/类型/转化/排序筛选的最小基线请求，只带 schema 必需 ASIN、站点、时间和分页参数。用户指定月份时必须使用；不得静默改为近 30 天。
- 从实际记录列表逐条读取关键词。常见路径可能是 `data.items[].keyword`，但不能预设；严禁从顶层 `data.keyword` 读词，也不能因顶层 null 判为无记录。
- 基线可读后才逐项增加排序、流量词类型或 badges；每次记录筛选前后数量。字段投影导致记录消失/顶层 null 时禁用投影并回到基线。总数为 0 且记录列表为空才是无记录；总数大于 0 而词字段不可映射是未获取。
- 为每个成功关键词响应记录实际时间范围；默认期未返回起止日期则记录“采用接口默认时间范围，具体期间未返回”。`traffic_keyword_stat`、`keyword_order` 等不是 `traffic_keyword` 的替代品。

## 4. 四阶段与用户确认

阶段零通过且必填项齐备后，先原样输出：

```text
整个文案的生成分为四个阶段：
阶段一：竞品信息抓取与候选卖点池
阶段二：最终五点确认、关键词布局与五点生成
阶段三：标题与商品亮点生成
阶段四：反查关键词补充 ST

首先执行第一阶段：竞品信息抓取与候选卖点池。
当前执行阶段：阶段一｜竞品信息抓取与候选卖点池
```

后续阶段在用户确认前一阶段后，先单独输出且仅输出一行：`当前执行阶段：阶段二｜最终五点确认、关键词布局与五点生成`、`当前执行阶段：阶段三｜标题与商品亮点生成` 或 `当前执行阶段：阶段四｜反查关键词补充 ST`。

### 阶段一：候选卖点池

先给出简短的多竞品归纳摘要：纳入数、2–5 个共性需求/痛点/场景、单竞品差异方向和数据缺口。共性信号至少应来自 2 个竞品；仅一个竞品时写为单竞品信号。评论去重后记录涉及竞品数和有效评论数；关键词按保守词根/完整词元去重。不得展示完整竞品标题、原始评论、关键词清单或逐 ASIN 原始数据。

候选卖点连续编号，每条必须包含：原创的消费者方向、证据来源、对应分母覆盖数、新品事实状态（已确认可写/待用户确认/仅需求参考）和建议位置（五点候选/A+）。保留候选 ID、用户状态、未使用原因和任何排除/确认决定，不重编号。

候选可覆盖功能与痛点、人群、场景、季节、搭配/兼容方向；任何事实变量未确认时只能作为待确认方向。阶段一结束时要求用户确认恰好 5 个最终卖点；多于 5 个可建议 5 个和 A+ 承接，但不能替用户选择；少于 5 个只请求补充方向。被选择的 5 个卖点仍须逐条通过事实复核，才能进入阶段二。

### 阶段二：五点、SEO 与可读性

只围绕 5 个已确认、可写卖点生成 5 条，一条对应一个卖点。结构为：核心特点总结 → 已确认特性 → 消费者收益/痛点 → 自然关键词。不得新增事实、绝对承诺、竞品资产或无意义同义词。

有大小写语言使用 `UPPERCASE KEY BENEFIT — 完整介绍`；无大小写语言使用 `【本地语言简短总结】— 完整介绍`。总结必须概括正文已有的事实/收益，且纳入字符和词密度统计。英文总结后的正文每条至少有一个完整句子，以便做 Flesch 检测。

阶段二输出：5 条五点、每条字符数、页面核心词频 Top10、关键词覆盖说明、合规/事实风险、适用停用词口径与英文 Flesch 结果。随后等待用户确认五点成品。

统计范围始终仅为最终标题 + 商品亮点 + 5 条五点；ST、表格、候选池、元数据和 A+ 不计入。对可可靠空格分词的语言，先用可复核的目标语言停用词表过滤功能词；用完整词元/可信词形归并统计，禁止局部字符串匹配。对不能可靠分词的语言，以完整确认词组的非重叠出现次数 × 词组字符数 ÷ 去标点空格的字符数计算，并说明停用词过滤不适用。

主品类每个有效词根（或不可可靠分词语言的完整品类词组）密度必须分别 ≥5.0%；辅助功能/场景/人群词最多 3 个，只展示实际频次与密度、不设硬门槛。若自然表达、事实边界和英文 Flesch ≥60.0 不能同时满足，暂停报告实际数据，不得靠堆词达标。英文 Flesch 只计算 5 条正文的完整句子；标题/亮点另查自然性、拼写和标点。

### 阶段三：标题与商品亮点

先列出标题保留项（品牌、主品类有效词根、必要变体）和 5 单元预算。内部格式启用时，首段为 5 个预先定义的关键词语义单元，第一单元是品牌；多词品牌可作为一个保护单元，多词主品类的有效词根必须全部落入首段。使用空格语言在第 5 单元后使用 ` - `；不以空格自然分词的语言按 5 个语义单元内部验证且保持当地自然书写。第二部分不得重复非必要首段词、明显同义词或品牌。若预算/长度无解，先请求用户选择规则修改。

标题满足有效上限后，建立仅含已确认事实、且未被标题占用的亮点素材。内部亮点是自然短语，用逗号连接，不用句号或完整句式；生成至少 3 个候选并逐一统计字符，交付最自然且最接近上限的安全候选。除必要的可读性识别词外，亮点不得重复标题的同一事实/主题；如存在必要重复，标记原因。

亮点必须落在有效区间。所有安全候选偏短时，暂停索要更多已确认事实；不能加入猜测或无关词。阶段三输出标题、标题字符数、亮点、亮点字符数、去重检查与关键词覆盖说明，并等待用户同时确认标题和亮点。

### 阶段四：ST

对每个纳入竞品重新按当前站点和时间口径执行 `traffic_keyword`：先无字段投影、无 badges/类型/排序筛选的最小基线请求，再从实际记录列表读取关键词字段；不要读顶层 `data.keyword`。只有基线证明记录可读后才逐项增加筛选，并记录筛选前后数量。

按 ASIN 写入关键词时间范围、基线结果和字段映射。状态必须是以下之一：

- `流量关键词完整可用`：所有纳入 ASIN 的基线可读或确认空列表；
- `流量关键词部分可用`：至少一条可读，但有未获取 ASIN；必须先获用户确认后使用可用部分；
- `流量关键词无记录`：全部已成功基线调用，且都为空；
- `流量关键词未获取`：没有可用关键词或能力/字段/调用无法确认。

“无记录”或“未获取”时，暂停最终交付并让用户在 A（补充并确认站点关键词清单）和 B（明确允许已确认新品事实兜底）之间选择。部分可用时若用户拒绝部分证据，也走 A/B；选择 B 必须如实标为新品事实兜底，不能称竞品反查。

从标题、亮点和五点建已覆盖词根集。仅选与确认新品事实相关、未覆盖、非竞品资产、非夸大和非未确认变量的词。空格语言使用单一 ASCII 空格分隔独立词元；无空格语言不强插空格。ST 单行、无逗号/句号/分号/短横线、无重复完整词元/可信词根，UTF-8 bytes 不超过有效上限。候选数据可用但全部被安全过滤时，允许 ST 留空且 bytes 为 0，并记录“无安全未覆盖词”；不要假称数据无记录或填充无关词。

## 5. 最终 Markdown 与自检

只在 4 阶段均完成、五点/标题/亮点均获确认、且 ST 的数据状态或兜底选择已闭环后，在当前可写目录/用户指定目录创建一个 UTF-8 `.md`。文件名使用 `Amazon_New_Listing_Final_<marketplace>_<YYYYMMDD_HHMMSS>.md`，不使用作者机器路径。无写入权限时如实报告，不能把聊天内容说成文件。

最终文件必须包含：

1. 交付信息：站点、页面语言、规则来源和有效限制、`M_detail/M_review/M_keyword`、原输入/排除/纳入 ASIN 清单及原因、关键词状态/日期范围/提取校验、事实边界；
2. 5 条本地语言卖点、标题和亮点，及真实字符数；
3. 一行 ST（允许为空）及来源、UTF-8 bytes、词根去重和页面词根排除结果；
4. 已确定的 5 个卖点明细、所有未使用候选明细（不含已剔除竞品资产或未确认竞品事实）；
5. 主品类/辅助词根密度表和独立的词频 Top10 表，二者均写明统计口径；
6. 英文 Flesch 结果或不适用原因、标题/亮点语言检查；
7. 仅以候选方向、评论需求和确认事实为依据的 A+ 建议（内容、模块、原因、待确认事实）。无建议时只写“暂无额外 A+ 建议”。

交付前核对：阶段提示与确认均存在；所有基础详情异常均获用户处理；证据分母未混用；新品事实来源可追溯；没有竞品资产或虚构新品表现；标题/亮点/ST 的有效限制通过；ST 数据状态不被安全候选为空混淆；密度/Top10/Flesch 的统计范围正确；实际写入的文件无花括号占位符。
