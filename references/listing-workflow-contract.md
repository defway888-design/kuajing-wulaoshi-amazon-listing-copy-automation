# 跨境吴老师 Amazon 新品 Listing 文案运行契约

本契约适用于根据一个或多个参考竞品 ASIN，为尚未上架的新品编写 Amazon 商品页面文字内容。参考竞品和新品必须始终分开：竞品数据只能说明品类、需求、场景、顾虑和关键词方向，不能成为新品事实或新品表现。

## 0. 阶段零：卖家精灵 MCP 配置门槛

每次运行的第一项动作都是完整读取 `sellersprite-mcp-configuration-gate.md`，并核验当前 Agent 实际暴露的 MCP 连接与工具目录。只有同一卖家精灵/SellerSprite 工具组中的以下三项能力均可唯一绑定，阶段零才通过：

- `asin_detail`：按 ASIN 和站点获取商品详情；
- `review`：按 ASIN 和站点获取评论列表或明确空列表；
- `traffic_keyword`：按 ASIN 和站点获取流量关键词列表或明确空列表。

服务未配置、未启用、未授权、未暴露工具、归属不明、候选工具不唯一、关键 schema 无法确认或连接失败，均视为未通过。失败时第一句必须写明具体暂停原因：

```text
跨境吴老师当前暂停 Amazon 新品 Listing 文案：<具体连接、能力、授权或绑定原因>。
```

随后要求用户在当前 Agent 配置、启用或授权卖家精灵 MCP 并重新加载工具。不得进入阶段一、切换其他数据源、猜测工具名称、读取作者机器配置、自动编辑用户配置或索取密钥。用户表示已经完成配置后，必须重新检查当前会话，不得沿用旧的工具清单。

如当前环境提供卖家精灵数据字典或数据库导引 Skill，可按该 Agent 的使用机制优先读取；不存在时，以当前 MCP 工具说明、入参 schema 和实际响应为唯一数据契约继续。辅助 Skill 不是硬依赖。

## 1. 初始输入、语言与有效规则

### 1.1 初始输入

阶段零通过后，开始阶段一只需要以下三类输入：

1. 目标 Amazon 站点；
2. 一个或多个参考竞品 ASIN；
3. 新品品牌词。

三类输入可以一次提供，也可以分多次补齐。缺少任一项时只询问缺失项，不调用竞品数据。主品类词不要求用户提前提供；阶段一结束时由 Skill 提供候选并由用户确认。新品事实与规格在主品类词确认后再收集。

ASIN 可用逗号、空格或换行分隔。去除首尾空格、统一为大写、按完全一致值去重，并保留首次出现顺序。ASIN 是否有效，以 `asin_detail` 在目标站点的实际结果为准；不得仅因 ASIN 为纯数字或不符合预设正则而拒绝。

### 1.2 页面语言

页面语言默认随站点：US、UK、AU、CA、IN 使用英文；JP 使用日文；DE 使用德文；FR 使用法文；IT 使用意大利文；ES、MX 使用西班牙文；BR 使用葡萄牙文；AE 默认使用英文。站点支持多种语言或用户要求不同语言时，先让用户确认。

流程沟通、证据解释、表格和检查结论使用中文。最终 5 条五点、标题、商品亮点和 ST 必须全部使用确认后的目标页面语言，不得用中文翻译、占位符或中外文混写代替成品。

### 1.3 默认限制与用户覆盖

默认内部交付规则：

- 五点：固定 5 条，每条最多 200 个 Unicode code points；
- 标题：严格少于 75 个 Unicode code points，即最多 74 个；
- 商品亮点：最多 125 个 Unicode code points；
- ST：最多 250 UTF-8 bytes。

上述限制以及标题前段计数规则均为本 Skill 的内部业务规则，不得描述为适用于 Amazon 所有站点、类目和账号的官方通用政策。

用户提供不同的站点、类目或账号后台限制时，只替换其明确指定并再次确认的字段。覆盖前展示原规则、用户规则和影响范围。规则互相冲突或无法同时满足时暂停，由用户选择；不得自行采用更宽松规则。最终交付记录本次实际生效的规则和来源。

## 2. 事实、安全与原创边界

- 不得声称尚未上架的新品已经拥有评论、销量、排名、历史表现、变体表现或认证。
- 不得复制或近似改写竞品标题、五点、A+、评论原文或关键词排列。
- 不得使用竞品品牌、店铺、型号、商标、专利、独家设计或其他可识别资产。
- 材质、尺寸、容量、重量、颜色、数量、适配对象、包装内容、功能、性能、认证、测试、质保和变体必须来自用户资料并获得明确确认。多个竞品共有也不能转化为新品事实。
- 竞品评论只能归纳需求、顾虑、痛点、场景和收益方向，不得写成新品已经收到的评价。
- 合规检查只表示事实、夸大和明显文案风险检查，不表示 Amazon、法律或监管审核已经通过。
- 新品资料与竞品信息冲突时，以用户最终确认的新品资料为准。

## 3. 竞品数据获取规则

### 3.1 工具与分页

工具名称、命名空间、请求包装、字段投影、分页字段、单批 ASIN 上限和响应容器均按当前运行环境的 schema 动态确认，不得写死。

对用户提供的全部 ASIN 逐一处理，不得只选一个或默认把某个 ASIN 的信息套用于其他 ASIN。多 ASIN 请求按工具声明的上限拆批；未声明批量上限时逐个处理。

评论与流量关键词默认执行接口可用范围内的全量分页，直到总页数、游标结束、空页、少于请求条数或重复页等实际响应证明已经到达末页。不得设置主观截断数量。临时错误只重试当前失败请求，最多 2 次；服务明确返回等待要求时按其要求执行。持续失败、游标不前进或连续返回相同记录时停止当前路由，说明已完成范围和缺口。

流量关键词始终使用卖家精灵接口默认时间范围。接口返回具体期间时如实记录；未返回时内部记录“采用接口默认时间范围，具体期间未返回”，不得自行推定日期。

原始响应、完整竞品标题、原始评论和原始关键词清单只在内部处理，不输出到对话或最终 Markdown。每完成一个 ASIN 或批次，只给出必要的简短进度。

### 3.2 基础详情与竞品相关性

先对全部 ASIN 调用 `asin_detail`，至少确认 ASIN、标题、品牌、类目路径或等价产品语义。基础详情失败、ASIN 无效或站点不匹配时，列明 ASIN 和具体原因并暂停，等待用户移除、替换或确认排除；不得静默丢弃。

按以下结果做相关性校验：

- 明显属于同一产品类型：纳入；
- 产品类型不明确：标记待用户确认并暂停；
- 明显属于其他品类：建议排除并说明依据，等待用户确认；
- 排除后没有可用竞品：暂停并要求补充 ASIN。

不得为了凑数量使用不相关竞品。父子体、竞品变体、价格、评分、上架时间和其他属性只作背景信息，不能成为新品变体或卖点事实。

### 3.3 评论与流量关键词

对每个获准纳入的 ASIN 调用 `review` 和 `traffic_keyword`。评论只提取实际可用的标题、正文、星级和时间并进行语义去重；不展示评论人信息、链接或大段原文。

流量关键词先执行无字段投影、无 badges、无类型、无转化筛选、无排序的最小基线请求，只携带 schema 要求的 ASIN、站点、默认时间口径和分页参数。必须从实际记录列表中识别关键词字段，不得从顶层 `data.keyword` 或类似路径猜测。只有基线证明记录可读后，才可逐步增加筛选，并记录筛选前后数量；筛选后为 0 不能反推基线无记录。

每个 ASIN、每条数据路由必须区分：

- 可用：成功读取记录；
- 无记录：调用成功且确认列表为空；
- 不可用：绑定、schema、字段映射、分页、授权或调用失败。

只要部分竞品或部分路由没有可用记录，阶段一先列出每个竞品的状态、具体原因和整体覆盖范围，再暂停等待用户明确同意使用现有证据。无记录与不可用必须分开表述，不得把失败称为空记录。

## 4. 四阶段与确认关卡

初始输入齐全后，先原样输出：

```text
整个文案的生成分为四个阶段：
阶段一：竞品分析与主品类词确认
阶段二：五点生成与五点词频词密度统计
阶段三：标题与商品亮点生成
阶段四：ST、整页综合统计与最终交付

首先执行第一阶段：竞品分析与主品类词确认。
当前执行阶段：阶段一｜竞品分析与主品类词确认
```

后续进入新阶段前，单独输出对应一行：

```text
当前执行阶段：阶段二｜五点生成与五点词频词密度统计
当前执行阶段：阶段三｜标题与商品亮点生成
当前执行阶段：阶段四｜ST、整页综合统计与最终交付
```

前一阶段或关卡未经用户明确确认，不得提前输出下一阶段提示或内容。

### 4.1 阶段一：主品类词候选

完成竞品核验和数据缺口闭环后，归纳竞品详情、评论需求和流量关键词，默认输出 3 个主品类词候选。候选使用目标页面语言，按推荐度排序，并用中文逐项说明依据。

依据优先级：

1. 竞品详情中的类目、产品类型和标题语义；
2. 流量关键词中的高相关品类表达；
3. 评论中消费者对产品的称呼，仅作辅助，不能单独确定主品类词。

每个候选都必须有可追溯证据。无法形成 3 个有证据的候选时，只输出能够支持的数量并暂停，请用户补充竞品或直接输入主品类词；不得凭模型常识凑足 3 个。全部竞品都不足以判断时，暂停并请用户补充或更换 ASIN。

用户可以选择、修改或自行输入主品类词。用户输入与竞品证据不一致时，说明不一致和依据并暂停；用户再次确认后，以用户输入为最终标准。后续核心品类词根、标题前段和词频词密度全部按最终确认的主品类词执行。

### 4.2 阶段间确认：新品事实、变体、卖点和辅助词根

主品类词确认后，提示用户为本次运行指定一个明确变体，并按结构化清单提供新品事实：

- 材质、尺寸、容量、重量、数量等规格；
- 核心功能和性能；
- 适用场景和目标人群；
- 颜色、款式和目标变体；
- 包装清单和兼容范围；
- 认证、测试、质保及其他需要证据的信息。

用户可以填写“不适用”或“未知”。多变体商品每次只生成一个变体的一整套页面文案；需要多套时逐个运行，不得混用属性。

收到资料后，先输出“新品事实确认表”，分为：已确认可写、表述不清待补充、需要证据支持、竞品专属或禁止使用。只有用户确认事实表后才可生成候选卖点。

候选卖点必须同时满足：

1. 至少对应一项已确认新品事实；
2. 有竞品详情、评论需求或流量关键词证明市场相关性；
3. 是原创的消费者方向，不是竞品句子或关键词堆砌；
4. 标明稳定候选 ID、方向、事实依据、市场依据、证据覆盖和适用范围。

同一需求至少出现在 2 个竞品中才称为“共性信号”。只出现在 1 个竞品中可以作为“单竞品信号”，但不得表述为市场共性；只有一个竞品时，全部市场依据均标为单竞品证据。

候选池限定为 5—10 个：

- 少于 5 个：暂停并说明缺少哪些新品事实；不得拆分同一事实、借用竞品事实或虚构内容凑数；
- 5—9 个：全部输出；
- 超过 10 个：按新品事实匹配度、多竞品覆盖、评论需求强度、关键词相关性和候选差异性综合排序，仅输出前 10 个。

不得把竞品销量、评分或排名解释为某个卖点必然有效。用户可以选择、删除、改写、排序或新增候选；最终 5 个卖点必须重新通过事实和市场相关性校验。用户确认正好 5 个后才可继续。

随后从最终 5 个卖点和已确认新品事实中提取功能、场景、人群方向，并用流量关键词验证相关性。排除停用词、核心品类词根、竞品资产、无关词和未确认事实后，向用户提供辅助词根候选；用户最终确认最多 3 个。辅助词根不设密度硬门槛。

### 4.3 阶段二：五点描述与阶段统计

只围绕已确认的 5 个卖点，按用户确认顺序生成正好 5 条；一条对应一个卖点，不得合并、拆分、调序或新增事实。

每条结构：`核心特点总结 → 已确认产品特性 → 消费者收益或解决痛点 → 自然关键词`。

- 有大小写语言：使用 `UPPERCASE KEY BENEFIT — body`；
- 无大小写语言：使用 `【本地语言简短总结】— body`；
- 总结必须准确概括正文已有事实或收益；
- 总结、分隔符、正文、空格和标点全部计入字符数及词频词密度；
- 每条最多 200 个 Unicode code points，无最低长度，不要求接近 200；
- 每条输出实际字符数；
- 禁止绝对承诺、竞品资产、无意义同义词和未经确认事实。

英文五点的 5 条正文各自至少包含一个完整句子；Flesch Reading Ease 只计算正文完整句子，必须达到 60.0。其他语言不计算 Flesch，只检查自然性、语法、拼写、标点和可理解性。

阶段二只对 5 条五点的完整成品执行词频和词密度统计，不包含标题、商品亮点、ST、候选池、表格或说明。统计和自动优化使用第 5 节统一规则，最多 3 轮。全部 5 条及检查结果作为一组输出，然后等待用户确认。五点未确认前不得生成标题或商品亮点。

### 4.4 阶段三：标题与商品亮点

#### 标题前段

对可按空格可靠分词的页面语言，标题前段必须正好包含 5 个“计数关键词”，并完整包含品牌词和主品类词。计数规则：

- 多词品牌按每个独立关键词计数，例如 `abc` 为 1 个，`abc ddd` 为 2 个；
- 多词主品类同样逐词计数，例如 `water bottle` 中 `water`、`bottle` 各计 1 个；
- 单独数字不计数；
- 计量单位计数，因此 `32 oz` 中 `32` 不计、`oz` 计 1 个，整个规格贡献 1 个；
- 数字与单位连写时整体计 1 个，例如 `32oz` 计 1 个；
- 带连字符的表达整体计 1 个，例如 `2-Pack`、`USB-C`、`3-in-1`、`Heavy-Duty`；
- 冠词、介词和连词不计数；
- 标题段落分隔符 ` - ` 不计数。

品牌词和主品类词合计不足 5 个时，只能使用用户确认的主要属性或必要变体补足。合计正好 5 个时无需属性词。合计超过 5 个时视为无解，暂停并请用户修改品牌展示、主品类词或本次规则；不得删除品牌或品类词。

第 5 个计数关键词后必须立即连接精确的 `空格-空格`，再书写标题第二段。先展示前段原文、逐项计数结果、未计数词明细和 5 词结论，等待用户确认。确认后不得静默修改；任何修改都要重新计数和确认。

日文、中文等不能按空格可靠分词的语言免除“正好 5 个计数关键词”和 ` - ` 规定，但仍须自然、完整地包含品牌和主品类词，并先让用户确认标题前部表达。

#### 完整标题

标题最多 74 个 Unicode code points；空格、标点和 ` - ` 全部计数。目标是在事实准确、语言自然、可读和不重复的前提下尽量接近 74 个字符；禁止为接近上限添加空洞词、同义重复或无关信息。

前段确认后，生成正好 3 个完整标题候选。可按空格分词的语言必须原样保留已确认前段。逐项输出字符数和检查结果，等待用户选择或修改并确认 1 个标题。全部标题候选输出后必须停止；标题未确认前不得生成商品亮点。

#### 商品亮点

标题确认后，建立仅含已确认事实且不重复标题信息的素材池，再生成正好 3 个候选。每个候选必须：

- 使用产品特性或优势驱动的短语，不写完整句子；
- 不以句号结尾；
- 不重复商品标题中已有的信息、事实或主题；
- 可以重新表达五点中的已确认事实，但不得复制五点句子；
- 使用目标语言自然的短语分隔方式，不强制使用逗号；
- 最多 125 个 Unicode code points，并输出实际字符数。

在自然、有用且不重复的前提下尽量接近 125 个字符；没有固定最低长度。“禁止凑数”优先于接近上限，无法自然增加时交付更短的最长安全版本。输出 3 个候选后等待用户确认其中 1 个；确认前不得进入 ST。

### 4.5 阶段四：ST、最终统计与交付

商品亮点确认后，对全部已纳入竞品重新调用 `traffic_keyword`，仍使用卖家精灵默认时间范围和最小基线请求。必须区分：

- 完整可用：全部竞品的基线均读取到非空关键词记录；
- 部分可用：至少一个竞品读取到非空关键词记录，同时至少一个其他竞品无记录或不可用；
- 无记录：全部基线调用成功且记录为空；
- 不可用：没有任何非空关键词记录，且至少一个竞品因能力、字段、授权、分页或调用问题未能确认结果。

部分可用时，列出每个竞品属于可用、无记录或不可用，说明准确原因和整体覆盖，然后暂停等待用户明确允许使用部分数据。暂停信息第一句先写具体原因，例如：

```text
跨境吴老师当前暂停生成 ST：卖家精灵流量关键词只有部分竞品数据可用，尚未获得使用部分数据的授权。
```

无记录或不可用时也必须先说明准确原因，然后让用户选择：

- A：补充并确认目标站点关键词清单；
- B：明确允许使用已确认新品事实兜底。

不得猜词。选择 B 时必须标记“新品事实兜底”，不能称为竞品反查关键词。

从最终标题、商品亮点和五点建立已覆盖词根集。ST 仅选择与确认新品事实相关、页面尚未覆盖、非竞品资产、非夸大、非无关和非未确认变量的安全候选。候选数据可用但全部被过滤时，允许 ST 留空且 bytes 为 0，记录“无安全未覆盖词”，不得凑词。

可按空格可靠分词的语言：ST 单行，词元间只用一个 ASCII 空格，无首尾空格，不使用逗号、句号、分号、短横线或其他标点，不重复完整词元或可信词根。无空格语言：保持自然书写，不强插空格，单行、无标点，按完整词组去重并排除页面已覆盖词组。所有语言均不得超过 250 UTF-8 bytes。

输出 ST、来源状态、实际 bytes、词根去重结果和页面排除结果，并等待用户确认。ST 未确认前不得执行最终统计或生成最终 Markdown。

## 5. 词频、词密度与可读性统一规则

### 5.1 两次统计的范围

1. 阶段二统计：仅 5 条最终五点，包括每条摘要、分隔符和正文；属于中间检查。
2. 最终统计：仅最终标题 + 最终商品亮点 + 5 条最终五点 + 最终 ST；在四类页面文字都确认后执行。

两次统计使用完全相同的分词、归一化、停用词、密度公式、核心词门槛和优化规则，只有统计范围不同。最终 Markdown 只显示最终整页综合统计，不重复展示阶段二数据。

### 5.2 可可靠分词语言

自动选择与目标页面语言匹配的停用词表。冠词、介词、连词及其他停用词从分母、频次、排名和密度中排除；不向用户展示停用词清单。

使用完整词元统计。大小写差异和可靠词形变化可以合并，例如 `bottle` 与 `bottles`；同义词、近义词和局部字符串不得合并。无法确认词形关系时按独立完整词元统计。

密度公式：

```text
目标归一化词根出现次数 ÷ 停用词过滤后的全部有效词元数 × 100%
```

### 5.3 不可可靠分词语言

主品类词按用户确认的完整词组处理，不拆成猜测词根；按非重叠出现次数统计。密度公式：

```text
完整词组非重叠出现次数 × 词组字符数 ÷ 去除标点和空格后的总字符数 × 100%
```

此口径不执行停用词过滤，并说明原因。只展示用户确认的核心和辅助完整词组，不自动生成普通词 Top10。

### 5.4 核心与辅助词根

核心品类词根来自用户最终确认的主品类词，不由竞品词频决定。可可靠分词语言中，主品类短语的每个有效词根都属于核心词根。例如 `water bottle` 必须分别把 `water` 和 `bottle` 作为核心词根。

若有 N 个核心词根，它们必须占据实际词频前 N 名，内部顺序不限；每个核心词根的原始未四舍五入密度必须分别不低于 5.0%。显示值保留两位小数，但达标判断使用原始值，例如原始 4.996% 即使显示 5.00% 仍判定未通过。

同频排名只用于解决并列：核心品类词根优先，辅助词根其次，普通词最后；同类型按首次出现位置排序。并列规则不得掩盖普通词实际频次更高的情况。

辅助词根最多 3 个，不设最低或最高密度硬门槛。展示实际频次和密度，并在不损害事实、自然性、长度和可读性的前提下尽量让其高于普通关键词；这只是优化目标，不是通过条件。

可可靠分词语言输出 Top10，字段为：排名、词根或关键词、类型、实际频次、实际密度、结论。核心词结论同时检查前 N 名和 5.0%；辅助词只显示实际数据；普通词不设门槛。

### 5.5 自动优化与回退

统计不通过时，在事实、自然性、长度和英文 Flesch 约束内自动改写、重算和复核，最多 3 轮。禁止关键词堆砌。3 轮后仍无法满足核心词要求时，第一句说明具体冲突并暂停。

最终内容确认后不得静默修改。最终统计不通过时，回退到受影响阶段，只修改必要内容，重新取得用户确认后再统计。ST 纳入最终分母但不能重复页面已覆盖词根；若 ST 导致密度下降，先删除低优先级 ST 词并重算，仍不通过时再回退页面内容阶段，绝不能把已经覆盖的核心词重新塞入 ST。

## 6. 最终 Markdown 与 A+ 建议

只有五点、标题、商品亮点和 ST 均获用户确认，最终整页统计及全部限制检查通过后，才生成一个 UTF-8 Markdown 文件。默认文件名：

```text
Amazon_New_Listing_Final_<marketplace>_<YYYYMMDD_HHMMSS>.md
```

默认保存到当前可写目录；用户指定保存位置时优先。无写入权限时如实报告，不得把聊天内容说成已生成文件。

最终文件包含：

1. 简要交付信息：目标站点、页面语言、规则来源、实际生效的标题/五点/商品亮点/ST 限制；
2. 用户最终确认的 5 条五点及逐条字符数；
3. 最终确认的 1 个标题和字符数，不保留其他标题候选；
4. 最终确认的 1 个商品亮点和字符数，不保留其他亮点候选；
5. 一行 ST、来源状态、实际 UTF-8 bytes、去重和页面词根排除结果；
6. 最终 5 个卖点明细及全部未使用的安全候选卖点明细，保留候选 ID、证据来源、覆盖范围、事实状态、未使用原因和建议后续方向；
7. 只针对最终标题、商品亮点、五点和 ST 的整页综合词频词密度结果；
8. 英文 Flesch 结果或其他语言的不适用说明，以及标题和商品亮点语言检查；
9. A+ 内容方向建议。

最终文件不输出原始竞品 ASIN 清单、纳入/排除 ASIN 账本、数据完整性账本、逐竞品数据状态、原始评论、完整竞品标题或原始关键词清单。阶段运行中的缺口披露仍必须完成，但不重复写入最终文件。

A+ 是最终附录，不属于四类页面文字，不纳入词频词密度。只输出安全的内容方向、推荐原因和待确认事实；不推荐 A+ 模块名称、类型或版式，不生成完整 A+ 文案。没有安全建议时只写：`暂无额外 A+ 建议`。

## 7. 暂停、修改与最终自检

任何暂停都必须先说明准确原因，再说明需要用户采取的动作。不得只输出笼统的“数据不足”或“无法继续”。

用户修改已经确认的主品类词、事实、卖点、五点、标题、商品亮点或 ST 时，回退到所有受影响的最早关卡，重新执行相关计数、事实、去重、密度、Flesch 和长度检查，并再次取得确认。

交付前核对：MCP 门槛通过；全部 ASIN 异常已闭环；主品类词和事实已确认；候选池数量与证据合格；5 条五点、标题前段、完整标题、商品亮点和 ST 均按顺序确认；阶段二统计范围只有五点；最终统计范围包含标题、商品亮点、五点和 ST；停用词口径正确；核心词排名和原始密度通过；没有竞品资产、虚构事实、凑字或堆词；最终文件没有未替换占位符。
